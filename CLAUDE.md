# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A **sample** Streamlit web app + planning artifacts for a semiconductor-fab engineer staffing simulator. It computes "FTE 확보" (FTE freed) per part → 그룹 → SITE → team when AX automation and part bundling (조직개편) are applied. The real product will be built later inside the company (DevOps); this repo is the pre-build sample. The user writes in Korean; UI text and docs are Korean.

`SPEC.md` is the source of truth for every rule (marked [확정]/[제안]/[미정], with a decision log and KEEP list in ch.13). Read the relevant SPEC section before changing calculation logic, and record new decisions there. Open questions for the user live in `REVIEW.md`.

## Architecture

- **Input = one Excel workbook with 5 sheets** (`templates/시뮬레이터_입력_샘플.xlsx`; order = tab order): **업무구분** (task master + one `"{year} 목표"` common-AX column per year, unbounded), **파트별 업무·실적** (yearly snapshot, key 연도+파트+코드: (입력) 빈도/단위/건당 = that year's pre-AX base, (회귀) 빈도 = locked regression forecast for future years (`regress_freq`: per part × 코드, OLS over 현재 연도−2..현재 연도, 1 year → slope 0, clamp ≥0; recomputed only by the settings [적용] button via `ui.apply_regression`; `freq_of` uses (입력) if present else (회귀)), 파트 목표 = part override **for that row's year only**, (입력) 자동화율 = reported actual (a blank year carries the previous reported year forward, else 0 — `Model.ax_rate/actual_year/reported`); a missing `"{year} 목표"` column falls back to the nearest earlier target year (`Model.target_year`), (실측) 빈도/건당 = survey), **조직변경** (1 row = 1 part: 연도, 구분 계획/실적, 변경 유형 신설/폐지/병합/그룹 이동/파트 묶음, 대상 파트, 결과 (적용처)), **인원** (yearly snapshot, key 연도+파트; missing in a later snapshot = closed → 재배치 대상 unless a 파트 병합 row (from that row's year on) says it was merged; 신설/폐지/그룹 이동 come only from the snapshots — 조직변경 rows for them are record/check only; no snapshot → previous one), **설비** (chambers/tools per part-year). Sheet/column names are constants in `app/sim/data.py` (`DICT, WORK, ORG, HEAD, EQUIP`, `IN_MIN`, `RESULT` …); `SHEETS` lists only input columns. Auto columns (JOIN 대분류~TYPE, (실측) 자동화율, 입력 안내, 상태) come from `display_table()` and are never stored. POR·현재 연도 are **not in Excel**: `config/settings.json` (`load_config/save_config`, `SIM_CONFIG` env var overrides the path — tests use it), held in `Dataset.settings`; `years_in_use(ds)` applies the same fallback as the engine. Old 11-sheet files are converted on import (`_from_legacy`, notes in `Dataset.notes`; fixture `tests/fixtures/legacy_11sheets.xlsx`). `check_table(name, df, ds, hidden=None)` is the save gate (errors with 1-based row numbers + non-blocking warnings, e.g. 총원 검산, ⚠️ 미반영 계획); `org_problems` checks 조직변경 rows against the 인원 snapshots; `validate` runs everything for the warning banner. **All Excel output goes through one writer, `app/sim/xlsx.py`** (app export, `templates/시뮬레이터_입력*.xlsx` via `tools/excel/make_input.py`, and the 업무구분 sheet inside the survey workbooks): columns = the 기준정보 screen columns (`display_table`) with auto columns as formulas, plus a final '입력 검사' column that mirrors the main rules — tested by `test_excel_columns_match_screen` and `test_excel_formulas_balanced` (an unbalanced formula makes Excel refuse to open the file). Survey/aggregation workbooks: `make_survey.py`, `make_freq.py` (조사 목적 기준/실적 → (입력)/(실측) columns of a 파트별 업무·실적 result sheet).
- **`app/sim/engine.py`** — pure calculation, no Streamlit. `Model` turns the Dataset into dicts. `build_profile` turns one part's 파트별 업무·실적 rows (`m.freq_rows(part, year)`: that year's work snapshot, or the 참고 파트's rows scaled by chamber ratio) into annual hours per location (DAY/SWING/GY/오피스), applying AX as `freq × (입력) 건당시간 × (1 − 자동화율)` (rate is per-occurrence time; the base is that year's (입력) 건당 — normally the POR value carried forward). `shift_need` = per-slot seats `ceil(max(workload, issue-day load, floor))` where floor = 최소 인원 (a 2-person slot is just 최소 2) / 물리 업무→1 / 교차 숙련→#parts; FTE = seats × 8h × 365 ÷ (2080 − 근무 외 비가동). `office_need` uses 260 days. Bundles (`m.bundles_at(year, plan)`: 조직변경 파트 묶음 rows grouped by 결과 name; '실적' rows always, '계획' rows only when `State.plan`) combine shift **and** office together: '합산' tasks add, '1회만' tasks take the max, floors take the max, issue reserves add. `Params.freq_growth` (설정 '미래 빈도') — False makes `freq_rows` use the 현재 연도 snapshot for later years. `evaluate(State, ax_year=…)` returns per-part results; FTE 확보 = (총원 − 재배치 대상) − 필요 인원. `Model.snap[year][name]` holds per-year `Part`s (`active_parts`, `part_at`, `snap_year`); `m.parts` = latest appearance (identity: SITE/그룹/직군). `m.por`, `m.cur`, `m.years` come from the config + data — never hardcode years.
- **`app/sim/scenario.py`** — `compare()` builds the REF→COMPARE FTE bridge in a fixed order (조직 변경 at REF's AX → AX → 묶음; plus 인원 변동 and 재배치 대상) whose steps must sum exactly (tested). Reorg options are only `REORGS = ("none", "plan")` (자동 묶음·내 묶음·후보풀 were removed on purpose — SPEC 2.4); '실적' bundles are in every step, so 묶음 효과 = '계획' bundles only. `trend()` (series `no_reorg` / `plan` / `actual`) feeds the dashboard chart and 인당 관리 챔버 수 (공정·설비 separately).
- **Dashboard** (`app/views/dashboard.py`): a single fixed view. `settings_panel(m, full=True)` (expander or pinned container, wrapped in an `st.form` — nothing changes until **✅ 적용**, which also reruns the regression; AppTest: `set_value(...)` then click 적용 without an intermediate `.run()`) = A 공통 조건 (POR·현재 연도, scope 직군 `ctl_job` / 그룹 `scope_group` / 파트 `scope_part`, REF·COMPARE·계획 묶음 반영·이슈·계산 옵션; changing POR·현재 연도 keeps the other submitted values; a '⚠️ 회귀 예측 갱신 필요' pill shows when `ui.regression_stale()` > 0) + B 차트 설정 (chart years, `ctl_met`, `ctl_unit`, `ctl_wl` 누적 막대/누적 비율/라인); 그룹보드 calls it with `full=False` (years + simulation only). `_scope(m)` → `names`/`job`/`label`, and every section re-aggregates with them: ① KPI cards (`scenario.seg_total`, raw 업무공수 hours via `ui.kpi_delta(hours=…)`, `ui.kpi_na` for empty segments) ② 인적자원 4 cols (people / trend / bridge / 교대·오피스 share) + part table with 상태 badge + bundle expander ③ 업무량 4 cols (per-person chambers, then 이벤트·루틴·이슈 frequency from `scenario.freq_series`: (입력) 빈도 × unit factor by 대분류, ◆ = 실측 반영 합계) ④ AX 효과 (대분류 saved-hours ranking | target vs actual rate, then 소분류 summary from `scenario.ax_detail`; COMPARE target = 예측, COMPARE actual = 실제 효과). 4-column rows use `_layout(align=True)` so plot areas line up. Scope filters use `scenario.Scope` (group/part by **that year's** snapshot, `inscope`; group moves from `Model.group_moves` are marked on the trend charts). Subset numbers re-sum stored `Result`s (`trend()["res"]`, `Compare.steps`) via `bridge_for / year_series / per_person(names=…)`; `ax_table` is shared with 그룹보드.
- **기준정보** (`app/views/master.py`): action bar, one plain tab per sheet (POR·현재 연도 are set in the shared 비교 설정 panel via `ui.set_years`). 인원 and 파트별 업무·실적 use `_yearly_tab` (per-year sub-tabs + ➕ 연도 추가 = `data.add_year(ds, y, name)`; 업무·실적 also has a 파트 필터 whose hidden rows go to `check_table(hidden=…)`). 업무구분 has the AX 공통 목표 일괄 적용 tool and the target-year tool (`data.add_target_year` / `drop_target_year`; the table shows only the latest `RECENT_TARGETS`=5 year columns unless toggled, hidden ones are merged back by 코드 on save); 파트별 업무·실적 has sub-tab 실적 보정 (reads (입력) vs (실측) of the same rows, writes (입력) 자동화율 + 비고 '조사 보정'); 조직변경 has the ⚠️ 미반영 계획 badge + 일괄 전환 button. `_sheet_block` = locked `st.dataframe` (Styler: auto columns gray, late plans orange, numbers pre-formatted as text so blanks are blank) ↔ edit mode (`st.data_editor`, auto columns disabled and dropped on save) → `ui.check` → `ui.set_table`; only one table in edit mode (`ss.edit`). Tools that write data go through `ui.save_table` (same check).
- **Menus** (in order): 📊 대시보드 · 🏢 그룹보드 · ⚙️ 기준정보 · 🗺️ 로드맵 · 📖 가이드.
- **로드맵** (`app/views/roadmap.py`): renders `docs/ROADMAP.md` only (the md is the single source — no screen text in code): first `##` section (플랫폼 비전) above the tabs, every later `##` = one tab, ```dot fences → `st.graphviz_chart`, blockquotes starting `> **🏭` → blue scenario box (`st.container(key='rm_case_…')` + scoped CSS). Each axis lists its related SPEC 13 KEEP items; KEEP items carry '→ docs/ROADMAP.md 축 N'.
- **가이드** (`app/views/guide.py`): 4 tabs rendering `docs/guide/01~04_*.md` (re-read on every run, no cache — edit the .md and refresh) + a .md download button per tab. The docs describe the real engine/screens; when calculation rules or screens change, update the matching doc (`tests/test_guide.py` also checks that '감축' is not used).
- **그룹보드** (`app/views/group_detail.py`, replaced 파트 정보): COMPARE per-group stacked bars, then **파트 부하 진단** (`app/views/diagnosis.py`, data from `scenario.part_loads / type_hours / load_status`): bubble chart (X 인당 챔버 = chambers ÷ 총원, Y 부하율 = 필요 인원 ÷ 총원 by default or 업무시간 ÷ 가용, 부족 > 110% / 적정 / 여유 < 90%), switches in order 보기 (그룹/파트, also drives the left bars) → 직군 (both charts) → 부하율 기준; page order = the two charts → 그룹별 상세 (below) → 파트 분석 at the bottom (`diagnosis.chart` then `diagnosis.detail`: `diag_part` selectbox or bubble click via `on_select`, 3-layer drill-down). Group detail: `grp_sel` multiselect with select-all/clear callbacks, per-group section (metrics, part table, 대분류 × part AX bar, per-part expanders with seats/AX). The dashboard's "그룹보드에서 보기" presets `grp_sel` + `detail_part`.
- **UI**: `app/ui.py` holds session state (`ds`, `version`, `params`, REF/COMPARE, `reorg` none/plan) and a per-version calc cache — call `ui.set_table()`/`ui.bump()` after any data edit. Pages in `app/views/` are plain `render()` functions wired with `st.navigation(position="top")`.
- **Sample data** comes from `tools/excel/sample_org.py` (18 parts, 2 SITEs × 3 그룹 × (공정 1 + 설비 2), plus 2027 P4 group, 2029 part closure; POR 2025, actuals 2026, yearly work snapshots 2025–2030 with ~4%/yr frequency growth) and `tools/excel/make_input.py` (calibrates POR workload per part to realistic levels the user confirmed: office 95–110% of capacity (>100% = OT), shift = busiest slot 90–96% of its seats — calibrated per slot because uneven 배치 like 1/1/2 with 1/3 교대 배분 would otherwise push one slot over 100%; result: POR office slightly short, shift FTE 확보 ≈ 0 every year (floors/1-seat slots), team FTE 확보 comes from office AX and planned bundles). Task codes (`E-EV-003` …) are assigned by order of `ROWS` in `make_dict.py` — inserting rows renumbers later codes.

## Terminology (easy to mix up)

그룹 = organizational unit (a part belongs to exactly one). 라인 = physical fab line (N:M with parts; not modeled yet). 묶음 (B1…) = simulated merge of parts. "감축" is never shown in the UI — use "FTE 확보".
